# 本地文件夹素材使用引用语义

## 决定

用户在自己设备上显式授权一个本地文件夹后，Flovart 只保存对该目录的授权句柄与相对路径，按需读取原文件；不把文件字节复制进项目存储。只有缩略图、视频封面和必要的代理文件进入本机缓存。

- 节点通过 `local-folder:<folderId>/<相对路径>` 引用素材，`sourceType` 标记为 `localFolder`。项目 JSON 不保存字节、base64 或临时 URL。
- 目录句柄保存在本机 IndexedDB（结构化克隆）。刷新后浏览器要求一次用户手势重新授权，界面据此提供显式“重新连接”，不静默降级。
- 句柄无法落盘时（例如宿主环境不支持句柄持久化），该文件夹仍可在本次会话内使用，并明确告知用户刷新后需重新选择。
- 原文件被移动、重命名或目录被删除时，读取失败按“请重新定位本地文件夹”提示，不按文件名猜测位置。
- 只把用户选中的条目放入画布，一次扫描不批量生成节点。
- 使用云端模型时，被引用的原文件会随本次生成发送给对应供应商；界面必须说明这一点。本地读取本身不上传。

## 背景

此前唯一的本地素材入口是导入副本：`ingestWorkflowMedia` 把 `File` 写入浏览器媒体存储。那满足“先落地再生成”，但不满足“素材就地读取”，大文件会重复占用空间，且用户的目录组织方式无法直接复用。

浏览器无法读取任意本地路径。因此本决策只覆盖用户在前端显式授权的目录。助手直接给文件夹路径的场景需要走 CLI/MCP 与本地服务读取，属于独立切片，必须单独做路径校验与权限边界，不能在前端用猜测路径实现。

## 与 0060 的关系

[0060](0060-use-a-desktop-authoritative-browser-import-bridge.md) 针对浏览器扩展从网页采集的链路，其要求是复制真实字节到内容寻址的 Artifact Store——因为那条链路面对的是 Native Messaging 大小限制、分块续传与网页来源溯源。本决策面对的是用户自己授权的本地目录，来源可信、路径稳定，复制只会带来无谓的磁盘与内存开销。

两者不冲突：扩展导入仍走复制与 Artifact Store；本地文件夹走引用。二者共用同一份下游能力（任务、Provider 输入、持久素材版本与渲染）。

## 后果

- 原文件与项目解耦，用户移动或重命名文件后必须重新定位；跨机器打开项目不会自动带上素材。
- 打包、导出与渲染必须能处理“引用失效”，在导出前检测并显式失败或要求用户旁路，不能静默输出错误内容。
- 目录授权依赖浏览器的 File System Access API；宿主 iframe 中可能被禁用，跨域注入场景不能承诺可用。入口适配需逐个验证。
- 需要为缩略图与封面维护独立缓存，且不能与 Workflow 媒体清理逻辑（按节点引用回收）混用同一存储实例。
