# Flovart 新用户操作手册

> 适用版本：当前主分支（2026-10-30）。部署方式见[快速开始](quick-start.md)，外部 Agent 见[Skill 指南](skill-guide.md)，Provider 认证状态以[支持矩阵](../../SUPPORT_MATRIX.md)为准。

## 1. 五分钟上手

1. 启动：`npm install` 后运行 `npm run flovart:cli -- start --source --web --open`，浏览器打开 `#/app` 的空白画布。
2. 添加 AI 服务：右上角「设置 → API」新增 Key。Closed Beta 推荐 RunningHub（图像 + 视频）；Gemini 与 OpenAI 兼容接口为 Experimental。自定义端点粘贴完整地址也会自动裁剪到 `/v1`。
3. 模型映射：「设置 → 模型」把文本 / 图片 / 视频能力指向具体模型。
4. 在画布双击或用工具栏新建生成节点，写提示词，运行。付费生成运行前会弹出费用确认。

## 2. 画布与节点

- 节点间连线即数据流：上游图片/视频可作为下游参考输入。
- **参数继承**：新建或下游生成节点自动沿用同模式节点的模型、风格、分辨率、时长、质量、音频设置；生成数量和参考素材不继承。
- **视频操作**：选中视频节点可截取首帧/尾帧、音视频分离，结果作为新节点放回画布并自动连线。源视频无音轨时会提示「无需分离」。
- **自动派生**：工具栏「工具」弹层可开启「自动截首帧 / 自动截尾帧 / 自动音视频分离」。开启后，新生成成功的视频会自动执行；默认关闭，打开已有项目不会触发。
- **拼接**：多段视频可用内置合并工具拼成一条（可配音轨）；精修建议导入 DaVinci Resolve。

## 3. 短剧工作流（推荐顺序）

1. **锚点**：先生成角色三视图、主场景、产品主视觉，确认满意。
2. **拆镜**：每个镜头一个节点，标题写镜号与内容，把锚点连为参考。
3. **批量生成**：互不依赖的镜头一次提交、一次确认费用；失败只重跑失败的镜头。
4. **成片**：用首/尾帧做镜头衔接，拼接后导出。

也可以直接对右侧 Assistant 说「把这个故事拆成 6 个镜头」，它会按上述顺序在画布上建节点，并在锚点确认前停下等你确认。

> 镜头与锚点：拆镜时每个镜头节点带 `shot`（镜号、时长、场景、机位、台词），角色/场景/产品/风格参考带 `anchor`。锚点节点标题栏有「批准锚点」按钮，点一下变为「已批准」，再点取消；操作可撤销，锁定节点不可切换。镜头生成前会自动连上已批准锚点；引用未批准锚点的镜头会被拦下并提示。拼接成片按镜号排序。也可以让 Assistant 或 `workflow.apply` 的 `update_node` 设置。

## 4. Skill

- **使用**：选择 Production Skill 后填写输入槽位（文本、长文本、图片、视频、音频、单选，最多 12 个）。
- **手动模式**：每一步付费生成都单独确认。
- **自动模式**：开始时设定一次费用上限；上限内不再询问，超出或范围变化会重新确认。
- **编写自己的 Skill**：

```bash
npm run flovart:cli -- skill.init my-skill      # 生成 flovart.skill.yaml、SKILL.md、agents/openai.yaml
npm run flovart:cli -- skill.validate my-skill  # 校验 manifest与输入槽位
```

槽位 id 须以小写字母开头（`^[a-z][\w-]{0,63}$`）；`skill.init` 不会覆盖已有目录。

## 5. 外部 Agent（Codex / Claude Code / OpenCode / WorkBuddy）

```bash
npm run flovart:cli -- status --json
npm run flovart:cli -- workflow.inspect --json
```

日常只用 `status`、`workflow.inspect`、`workflow.selection.get`、`workflow.apply`、`workflow.node.run`；`ensure` / `doctor` 用于连接与诊断。Agent 不会拿到你的 Provider Key；工具可调用不等于已批准付费。

## 6. 用量与费用

「设置 → 用量」按今天 / 近 7 天 / 全部统计，分两块：Token 用量按 Provider 与模型汇总调用次数、输入、输出、合计（含缓存与推理 Token）；「图片 / 视频费用」按模型汇总调用、失败次数和费用。

- 只统计服务商响应中返回的 usage，不估算。流式调用在完成、取消或出错时都会结算已下发的 usage；全程没有 usage 的流式调用只计次数，显示为「N 次流式调用未返回 usage」。
- 已覆盖：文本生成、提示词润色、图片反推（流式与非流式）、内置 Assistant、图片/视频生成费用。记录来自多个来源时，可按来源筛选。
- 未覆盖：托管 Agent（服务端）的 usage 只在服务端，本机暂不统计。
- 想让 OpenAI 兼容网关在流式中也返回 usage：在「设置 → API Key → 编辑 → 流式用量」切到「请求 usage」。只影响该 Key 的图片反推和内置 Assistant；网关不支持时（400）会自动去掉该参数重试，本次会话内不再尝试。默认关闭。
- 图片/视频费用按 API Key 里配置的定价规则预估，有实际账单时以实际为准；已退款和不计费的不计入；没配定价的调用显示为「未定价」。
- 数据只存在本机（最多 2000 条），可一键清空。

## 7. 与 LibTV / RunningHub RHTV / Higgsfield 对比

> 竞品一栏来自视频观察与公开资料，尚未逐条对照官方手册复核。

| 能力 | 竞品常见做法 | Flovart |
| --- | --- | --- |
| 画布节点工作流 | LibTV 画布、RHTV 工作流 | ✓ 无限画布 + 节点 |
| Agent 对话建节点 | LibTV 侧栏 Agent | ✓ 内置 Assistant + 外部 Agent CLI/MCP |
| Skill 输入槽位 / 自动模式 | LibTV | ✓ 6 种槽位、费用上限授权 |
| Skill 编写与安装 | Skill 生态 | ✓ `skill.init / skill.validate` |
| 参数继承 | LibTV | ✓ |
| 截帧 / 分离上画布 | 常见 | ✓ 含自动模式 |
| 多模型路由 | RHTV | ✓ schema 路由 |
| 用量透明 | 积分展示 | ✓ 文本 Token（含流式）+ 图片/视频费用；无 usage 只计次数 |
| 短剧分镜 | LibTV / Higgsfield | ✓ 结构化镜头（镜号/时长/场景/机位/台词） |
| 成片拼接 | 常见 | ✓ 按镜号拼接；时间线精修交给 Resolve |
| 角色一致性 | Higgsfield 角色 ID 类（待复核） | ✓ 已批准锚点自动接入，未批准则阻断 |
| 本地优先执行、内容寻址素材 | 多为云端 | ✓ Flovart 特有 |

**覆盖度（诚实口径）**：按[复刻方案](../design/30-competitive-replication.zh-CN.md)的 14 项机制，14 项均已实现。用量一项的精度取决于服务商是否在流中返回 usage，缺失时只计次数；托管 Agent 的服务端 usage 不在本机。另有一处已知取舍：不内置时间线（交给 Resolve）。竞品一栏仍待对照官方手册复核。

**稳定性与时延**：ffmpeg 任务串行避免冲突；自动派生防递归；文本请求固定低温、格式失败仅重试一次；每次请求记录首字节时延（ttfb）；批量生成失败只重跑失败节点。

## 8. 常见问题

- **打开 37522 端口但 Agent 未绑定**：请用 `start --open` 的启动握手链接，直接地址只是普通页面。
- **音视频分离报错**：源视频可能无音轨。
- **用量页为空**：Token 部分可能是服务商没有返回 usage（流式调用会显示「未返回 usage」次数）；费用部分可能是该时间段没有图片/视频生成。费用显示「未定价」：给对应 API Key 配置定价规则。
