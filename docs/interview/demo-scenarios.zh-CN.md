## 1. 一个选题到 60 秒成片（Reddit 政治热点）

来源：tools/flovart/evaluations/reddit-politics-2026-07-25/evaluation-report.md

问题
- 用户只给一个话题，能不能由 Coding Agent 通过 Flovart Skill + CLI 完成研究、素材生成、任务监控、后期和交付，并把过程同步到可见画布。
- 政治题材有事实风险：不能推断未证实的死因，不生成可识别政治人物的写实肖像。

现场演示步骤
1. npm run flovart:cli -- tui，展示 Runtime / Workflow / Tasks / Events 四块状态。
2. 在 TUI 里输 /research 美国政治，或用 research.topic.collect 拉 Reddit，讲“来源覆盖状态”字段。
3. workspace.status 确认 ready 后，用 workflow.inspect 和 workflow.node.update 现场改一个节点标题，画布实时变化。
4. 播放成片，指出一帧带英文标签的静帧，引出 OCR Gate。

可量化结果
- 同一环境下，last30days 基线因 Reddit JSON 403 拿到 0 条证据；Flovart Adapter 通过系统代理拿到 25 条 Reddit RSS 条目。
- 素材任务 10/10 成功（5 张 GPT Image 2 + 5 段 Grok 1.5），价格预览合计 ¥1.70。
- 旧的 5 秒 Grok 参数在价格预检返回业务错误 1007，Runtime 在提交前拦下，没有产生 Provider task ID。
- 追加 8 个任务的顺序队列 499.548 秒；从首个 tracer 到最后素材 1,338.374 秒（含参数失败与重启）。
- 成片 60.000 秒、1280×720、24 fps、10 段中文硬字幕；画布由 CLI 创建 4 节点 3 连线，浏览器 console error 为 0。
- 自评 7.2 / 10：制作能力 8、控制可靠性 8、自动化完整度 6、UGC Skill 就绪度 5、可观测性 8。

对应产品 / AI 能力
- Agent 编排与工具设计：幂等键、价格预检、来源覆盖状态都是命令契约的一部分。
- 内容安全与事实边界：选中性制度解释角度，引用 AP 与地方公共广播核实。
- 诚实的评估口径：可工作的制作内核，还不是一键交片的产品。

## 2. 科普短片 + 预算门禁 + 画布投影（为什么天空是蓝的）

来源：tools/flovart/evaluations/vox-sky-blue-2026-08-04/evaluation-report.md

问题
- 生成要花钱，用户需要先看到报价、设上限、再批准。
- 后端生成的过程要实时出现在画布上，设计师还要能二次修改（HITL）。

现场演示步骤
1. 展示 production.dry-run 编译出的 20 个 StageRun DAG 和 route plan 报价。
2. 讲 production.approve：硬上限 ¥5.00。
3. 播放画布录屏：节点 loading → success，关键帧升级为 image、动态镜头升级为 video。
4. 现场 move / resize 一个投影节点，说明安静期不回弹。

可量化结果
- 确认费用 ¥2.72，与 route plan 预估一致；硬上限 ¥5.00。
- 8 张关键帧 + 8 段图生视频全部成功；run 执行 27m50s，19 成功 / 1 blocked（无音乐 capability）。
- 成片 30.000 秒、1280×720，delivery:verify 全部通过；质量门禁 100/100、零 violation。
- 权威投影 21 节点 + 18 连线，workflow.inspect 确认 21 个节点都在可见画布上；投影约每 1.5 秒轮询。
- move (420,120)→(520,400) 经 4 个刷新周期不回弹。

可以主动讲的 Bad Case
- BC-RUN-001（P0）：依赖判断不认 skipped，导致 run 永不终态、占住唯一调度线程；用 task.cancel 释放并修复。
- BC-MEDIA-001：视频不显示，逐层定位到 Tauri ACL、CSP 缺 media-src、激活守卫三层，全部修复后用户确认可播。
- BC-HITL-001/002：重新 dry-run 或活跃物化期会覆盖手动布局，是尚未解决的边界。

对应产品 / AI 能力
- 成本可控：quote → approve → submit。
- 人机协作：AI 生成，设计师在画布上保留控制权。
- 从“后端出片再投影”转向“Agent 在画布上直接搭”的 AI-Native 判断（见 ai-native-canvas-blueprint.md）。

## 3. 文生视频直出 vs 关键帧路线（1776 年 Adams 与 Franklin）

来源：tools/flovart/evaluations/vox-history-1776/evaluation-report.md

问题
- 直接文生视频是否足够做风格化短片？跨镜头一致性和文字污染是否可控？

现场演示步骤
1. 并排播放镜头 1 和镜头 3：镜头 1 生成了 VOX 标识、后期用同色纸片遮盖；镜头 3 是质量最佳镜头。
2. 对比场景 2 的关键帧 → 图生视频路线，说明工作流为什么改。

可量化结果
- 4 个 8 秒镜头 4/4 成功，顺序生成总耗时 13m 24.837s，平均单镜头约 3m 21s。
- 提交前预估合计 ¥10.24（每镜头 ¥2.56）。
- 成片 30.000 秒，响度 -16.1 LUFS、True Peak -1.5 dBFS，校验全部通过。
- 对照：场景 2 的 8 关键帧 + 8 动态镜头确认 ¥2.72。两次模型和镜头时长不同，只能说明路线选择对成本影响很大，不是严格 A/B。

对应产品 / AI 能力
- 用实测证据做路线决策，而不是凭感觉选模型。
- 对第三方 Skill（vox-director）的判断：吸收为创意模板，但凭据、路由、账本由 Flovart 独占。

## 4. “读到了凭证却不能用，那有啥用”

来源：tools/flovart/evaluations/runtime-model-mapping-2026-08-03/evaluation-report.md；场景 2 报告中的 BC-CRED-001

问题
- Runtime 里有 RunningHub 凭证和 4 条路线，但网页“模型映射”只显示“请先在 API 配置中添加 Provider”。用户把正确的安全拒绝误认为凭证失效。

现场演示步骤
1. 打开设置 → 桌面 Runtime 凭证，点“一键导入到 API 配置”。
2. 切到模型映射，展示 G-2 / Grok / Veo 路线建议。
3. 讲清楚：网页端拿到的是不含明文的 runtimeManaged Key，生成请求经 Runtime 执行，明文只在系统 Keyring。

可量化结果
- 定位阶段：4 个测试文件通过，32 项断言通过，1 项 it.fails 准确锁定缺陷；本轮没有触发任何付费生成。
- 四个假设逐一排查：路线 ID 不一致被排除，断点在 Runtime 状态到模型映射页之间。
- 已实现一键导入与路由；报告里标注“待实机验证生成”，面试前要么补测一次，要么如实说。

对应产品 / AI 能力
- 把用户原话转成可测试的 Bad Case，再分清“安全边界”和“体验缺口”。
- 这类问题在企业 AI 产品（如 HR 数字化、办公套件）里很常见：权限对了，但用户看不懂为什么用不了。

## 5. 浏览器插件 × 网页画布

来源：docs/blog/2026-11-03-extension-web-canvas-bridge.md

问题
- 只用网页画布的用户没有右键导入通道；旧版本的 Key 以可读形式存在插件存储里。

现场演示步骤
- 不做现场操作：端到端还没在真实 Chrome / Edge 里跑过。用博客里的调研对比表讲取舍。
- 重点讲一个决策：配对只能在插件 popup 里批准，网页只能申请，信任根不在网页里。

可量化结果
- 导入链路 6 个文件 24 个用例、Key 同步 11 个文件 44 个用例、反推网关回归 3 个文件 99 个用例通过。
- 全量 vitest 246 个文件首轮 244 通过、2 失败：一个按新边界改写后通过，一个与本次无关。
- 限额：单个导入媒体 64 MiB、反推图片 20 MB、单个 origin 最多 200 个 Key。

对应产品 / AI 能力
- 安全与体验的权衡：多一步配对操作，换取信任根不在网页。
- 如实列出未做的验证和遗留，这本身就是产品判断力的展示。

## 6. Agent 操作画布的可靠性（2026-11-03 现场修复）

来源：本机 2026-11-03 测试输出；agent/session.js、agent/index.js、services/workflowDispatcher.ts

问题
- 演示中用 Agent 删除节点，返回笼统的 INTERNAL_ERROR，之后的调用都卡住。根因：删除是高风险命令，要在画布上等人点“允许 / 拒绝”，但 Agent 只给了 60 秒普通超时，超时后又被吞成 500。
- Agent 建节点时不给坐标，节点全部叠在 (0,0)，画布很乱。

现场演示步骤
1. 让 Agent 删除一个节点，画布弹出确认；故意不点，展示返回的是带错误码的超时而不是 INTERNAL_ERROR。
2. 让 Agent 从一个参考图连续拉出两个节点，不给坐标，展示它们在上游右侧对齐成一列。

可量化结果
- 删除超时修复：会话层 21 个测试通过，其中 3 个新增回归用例。超时返回 504、取消返回 499，超时标记为不可自动重试，避免重复写入。
- 自动排版：4 个相关测试文件共 59 个用例通过，其中 3 个新增。同一上游连续建两个节点落在 (436,0) 和 (436,280)。
- 以上都是单元测试结果；Agent 服务重启后在真实画布上复测一次再拿去演示。

对应产品 / AI 能力
- Agent 的高风险操作必须有人在回路，而且等待人的时间不能套用机器超时。
- 错误要对 Agent 和人都可读：笼统的 500 会让 Agent 盲目重试。
- Agent 的产出要对人友好：画布是设计师要接手的产物，排版乱就是产品问题。

## 7. 奶蛙 → 系列表情图标（未运行）

来源：examples/emoji-logo-series/PLAN.md

问题
- 给 2 张角色图 + 1 张风格图，在画布上搭一条可编辑的风格迁移流水线：第 1 列黑白图标 ×4，第 2 列上色 ×4。

现场演示步骤（计划）
1. Agent 在画布上建 3 个参考图节点和第 1 列 4 个图生图节点，提示词写在节点上、可编辑。
2. 用户确认后只跑第 1 列；满意后再跑第 2 列。

可量化结果
- 未运行。花费、用时、重跑次数实跑后填写，不挑图。

对应产品 / AI 能力
- 场景 2 里提出的 AI-Native 画布直搭范式的小规模落地：过程在画布上，设计师可以接手修改。

## 演示顺序建议

5 分钟版
1. 场景 2：报价 → 批准 → 画布实时投影（录屏 90 秒）。
2. 场景 6：现场让 Agent 建节点和删节点，讲人在回路。
3. 场景 4：用一句用户原话收尾，讲安全与体验的区分。

15 分钟版：在 5 分钟版前加场景 1（完整链路与自评分），在场景 2 后加场景 3（用数据做路线决策）。

岗位对应
- AI HR 数字化产品：场景 4（权限与体验）、场景 6（高风险操作的人工确认）、场景 2（成本审批流）。
- WPS AI 产品：场景 6 与 7（AI 在编辑器里留下可编辑的结果）、场景 5（插件与网页协同）、场景 1（内容安全边界）。
