## 已记录回归：workflow.project.use 浏览器激活缺失

- 症状：外部 Agent 运行 `workflow.project.use --project-id X` 后返回 `ok` 与 `{ projectId: X }`，但 `/health`（`workspace.status`）的 `activeProjectId` 仍是旧项目；后续 `workflow.inspect --agent-identity codex` 读取的仍是旧项目，若再对 X 显式传 `--project-id X` 会被 `agent/session.js:355` 以 `LEASE_TARGET_CHANGED` 拒绝——`project.use` 表面上成功，实际没有切换 agent 侧绑定目标。
- 根因：命令只穿过 Browser 执行，且没有任何「切换确认」握手。链路为 `cli.js → FlovartWorkspaceClient.execute → POST /api/tools → agent/session.js callCommand:331 → SSE tool_call → services/workflowAgentBridge.ts:270 → workflowDispatcher.ts:242-246`。`workflowDispatcher.ts:244` 的 `dependencies.setActiveProject(projectId)` 只改浏览器 store 的 `activeProjectId`（`components/workflow/store.ts:191`），随后 dispatcher 立即返回 `{ projectId }`——它只是回显请求参数，不是浏览器已切换的 ack。agent 侧绑定要等浏览器 store 订阅触发 `workflowWorkspaceAdapter.update()` → `pushSnapshot` → `POST /workflow/state` → `agent/session.js:96-117 updateSnapshot` 后才更新；由于 `project.use` 不在 `LEASED_WORKFLOW_COMMANDS`（`agent/session.js:7-12`）内，session 对该命令不取 lease、不等快照，resolve 时机早于回环完成。在这段窗口内 `callCommand:347` 的 `boundSnapshot` 仍是旧 projectId：`/health` 的 `activeProjectId` 读旧值，对 X 显式传 `--project-id` 的后续写入会被 `callCommand:355-365` 以 `LEASE_TARGET_CHANGED` 拒绝，而不带 projectId 的 `inspect` 读到旧项目。本地指针更新（`setActiveProject`）被当成交互终点，browser→agent 的状态回环完全在临界区之外。
- 预期语义（浏览器激活命令）：`project.use` 应是一条浏览器激活 RPC，而非普通 mutation——`callCommand` 收到后向 Browser 发送「切到项目 X」请求；浏览器 `setActiveProject(X)` → store 变化触发 `pushSnapshot(X)` → session `updateSnapshot` 把 `boundSnapshot.id` 更新为 X → 此时才向调用方 resolve，并让下一次 `ensureWorkspaceLease` 在 X 上签新 lease。当前实现把「本地指针更新」当成交互终点，绕过了 browser→agent 的状态回环，于是 inspect/lease/写目标三者各自依据不同时间点的快照。
- 为何暂不修：不在 5/5 Golden Task 的关键路径上——trial 走 `workflow.project.create`（新项目自动成为 active 并经 pushSnapshot 自然绑定），`project.use` 只在「跨已有项目切换」场景才暴露；修复需要在 session ↔ browser 之间新增一轮「切换确认」握手的真实行为改动，按用户指示作为独立回归跟踪，不混入本轮外部门禁收尾。预期语义已冻结为 [ADR 0072](../../../adr/0072-project-use-is-a-browser-activation.md)。
- 修复草案：把 `workflow.project.use` 加入 leased/确认命令集，或在 `callCommand` 里对它特判为「发送 tool_call → 等 boundSnapshot.id === args.projectId（带超时）→ resolve」；同时让 `workflowDispatcher.project.use` 分支在浏览器侧返回新 `activeProjectId` 作为 ack 载荷，而不是仅回显请求参数。
