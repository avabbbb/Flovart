## 第一阶段：Resolve Studio 21.1 MCP-first

当前第一宿主已切换为 **DaVinci Resolve Studio 21.1**。目标不是先开发更大的插件，而是先证明 Blackmagic native MCP + Flovart Skill/CLI + durable artifact + Media Pool 的真实纵向闭环。专项 UI/交互见 [Resolve 21.1 Product & UI Spec](../../../../integrations/studio/resolve/PRODUCT_UI_SPEC.md)。

- [ ] 在真实 Resolve Studio 21.1 中执行 `File > Setup AI Assistants`，验证一个真实外部 Agent（优先 Codex）连接；记录 Resolve build、OS、Agent 版本、实际 MCP tool surface 与连接配置，不用社区工具数量替代本机事实。
- [ ] 用 native MCP 读取当前 project / timeline / Media Pool selection，冻结 project + selection identity；用户随后切换选择时，进行中的 Flovart 任务不得 retarget。
- [ ] 第一条 Golden Task 不依赖真实 Provider：当前选择 → deterministic/fake Flovart artifact → durable file → **Add to Media Pool**；原 Timeline 保持不变。
- [ ] 修复 Resolve 当前 shared inspector 的输出项：`index.js` 传入 `{ kind: 'media-pool' }`，但通用 output select 目前未创建 Media Pool option。真实面板必须明确显示 `Output: Media Pool`。
- [ ] 按 Resolve Inspector / Media Pool 视觉规律重做轻面板层级：Connection → Current Clip → Generate → References → Model(Auto) → Output → Task → Candidates → Open in Flovart。不要做全屏 chat、MCP 管理页、模型商城或第二份 Timeline。
- [ ] 面板完成 no-project / no-selection / ready / running / candidate / disconnected / error 状态；窄宽窗口实测，无横向滚动，当前选择与 pending target 必须能同时被用户理解。
- [ ] P0 candidate 只允许 Preview + Add to Media Pool。P1 才做 Add to new track；P2 Replace/Commit 必须显式确认、提交前重新读取 target identity，并验证 undo/recovery。
- [ ] 真实 Studio 环境验证媒体文件生命周期：Resolve 导入后临时文件不能立即删除导致 offline media；落盘 Artifact 由 Flovart 持久管理，Media Pool 指向可长期读取的文件。
- [ ] Windows 下实测英文与中文 project/bin/marker/text；社区报告的 Python UTF-8/CJK 问题只有复现后才加入 `PYTHONUTF8` 或转义策略。
- [ ] native MCP 有 bounded / unsafe script surface 时默认只用 bounded path；unsafe filesystem/network escape 不为 Demo 自动开启。
- [ ] 接一个且只接一个已批准 RunningHub 路径：selected clip → real generation → durable artifact → Media Pool。记录计费、取消、429、unknown-after-submit 与重连语义。
- [ ] Hero 录屏固定为 20–35 秒：选中 Resolve clip → Agent 读上下文 → Flovart 真生成 → panel 出 candidate → Add to Media Pool。加速等待必须标注，不把 mock 当真实生成。

## 下一步：轻面板与素材入口

按“给本地 Agent 加一个随手可用的创作小功能”方向收敛：对话归助手，文件留在本地，任务只保存一份，面板与画布只是查看和编辑入口。本地文件夹直读已落地（见[待测试确认](pending-test.mdx)与 [ADR 0071](../../../adr/0071-local-folder-reference-media.md)），下面是剩余部分。

- [ ] 轻面板壳只保留「素材 / 任务 / 打开画布」三个入口，不再要求用户二次配置 Agent 或进入重复的制作控制面。「素材」已有真实实现，需要与「任务」「打开画布」收敛到同一面板，并确定唯一挂载位置（`/dock` 宿主嵌入面或画布内浮层），不新开第三个并列入口。
- [ ] 交互可参考 WorkDaddy 的小按钮与输入框旁快捷操作，但其 CDP 注入不是默认连接方式；各助手入口适配单独验证，不承诺 Codex 支持同样的界面注入。宿主 iframe 中目录授权可能被浏览器禁用，需提供降级入口并逐个实测。
- [ ] 助手直接给文件夹路径的读取走 CLI/MCP 与本地服务：需要在本地服务新增受限目录读取接口，做路径校验、授权范围与最小权限设计；不能在前端用猜测路径实现，也不能因为已支持目录授权就宣称该路径已通。
- [ ] 导出、打包与渲染需要处理“引用失效”：导出前检测缺失并显式失败或要求用户明确旁路，不能静默输出错误内容。
- [ ] `ingestWorkflowMedia` 继续服务文件粘贴与外部来源（导入副本语义不变）；不要把文件夹引用改写成同一条复制路径，也不要让新增缓存与 Workflow 媒体清理共用同一存储实例。
