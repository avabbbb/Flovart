# 后端数据库结构

Flovart Hub（`backend/` 目录）使用 PostgreSQL，GORM AutoMigrate 自动建表。本文件随表结构变化同步更新。

## users — 共享生态用户

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | uuid PK | `gen_random_uuid()` 默认 |
| username | varchar(32) unique | 字母数字下划线，3-32 位 |
| email | varchar(255) unique | 小写存储 |
| password | varchar(255) | bcrypt hash，不出现在 JSON |
| bio | varchar(500) | 个人简介 |
| avatar_url | varchar(500) | 头像 URL（R2 链接） |
| role | varchar(16) | `user` \| `admin` |
| created_at | timestamptz | |
| updated_at | timestamptz | |

## prompt_packs — 提示词包

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | uuid PK | |
| slug | varchar(80) unique | URL 友好标识 |
| title | varchar(120) | |
| description | varchar(1000) | |
| author_id | uuid FK → users.id | |
| mode | varchar(24) | `image` \| `video` \| `text` |
| tags | text[] | PostgreSQL 数组 |
| like_count | int | 反规范化计数 |
| download_count | int | 反规范化计数 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

## prompt_items — 提示词包内单条提示词

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | uuid PK | |
| pack_id | uuid FK → prompt_packs.id | |
| name | varchar(120) | |
| prompt | text | |
| sort | int | 包内顺序 |

## prompt_likes — 提示词包收藏关系

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id | uuid PK | |
| pack_id | uuid PK | |
| created_at | timestamptz | |

## 索引

- `users.username` 唯一索引
- `users.email` 唯一索引
- `prompt_packs.slug` 唯一索引
- `prompt_packs.title` 普通索引（关键词搜索）
- `prompt_packs.author_id` 普通索引
- `prompt_packs.mode` 普通索引
- `prompt_packs.like_count` 普通索引（热门排序）
- `prompt_likes(user_id, pack_id)` 复合主键

## 待扩展（工作流生态阶段）

`workflow_packs` / `workflow_items` / `workflow_likes` 表将在工作流生态阶段加入，结构参考 prompt 系列；工作流包不会保存模型配置或 API Key。

## 本机 Agent 视频流水线存储（不属于 Hub）

Agent 视频流水线的 trace 存在用户本机，和 Hub 的 PostgreSQL 无关，也不同步到云端。它与桌面 Production Runtime 共用同一个 `flovart-state.db`（`<app_data_dir>/flovart-state.db`，identifier `com.flovart.desktop`），表由 migration 5（`tools/flovart/contracts/runtime/migrations/0005_agent_pipeline.sql`）建立：Rust `RuntimeStore` 和 Node `tools/flovart/pipeline/store.js` 执行同一份 SQL，并共用 `runtime_migrations` 账本。Node pipeline 边界是唯一写入方；Rust Runtime 只通过 `pipeline.run.get` 读取，返回与 Node `Pipeline.trace()` 相同的 JSON（`npm run e2e:pipeline:parity` 校验）。产物文件放在 `<app_data_dir>/pipeline/`；`FLOVART_PIPELINE_HOME` 可把数据库和产物一起改到指定目录（测试与隔离用）。

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `pipeline_runs` | 一次制作 run | `id`、`project_id`、`status`（active / blocked / passed / archived / stopped）、`budget_json`、`blocker_json`、`head_version` |
| `run_steps` | 命令边界自动记录的 Step | `run_id` + `seq` 唯一；`tool`、`caller`、`mutation_id`（`run_id, tool, mutation_id` 唯一）、`args_digest`、`status`、`attempts`、`artifact_ids_json` |
| `pipeline_artifacts` | 内容寻址产物 | `sha256`、`kind`、`path`、`media_json`、`params_json`、`rejected` |
| `pipeline_spec_versions` | 合成 spec 修订 | 主键 `run_id, version`；`parent_version`、`spec_sha256`、`diff_json` |
| `pipeline_renders` | 每个版本的渲染 | `version`、`preset`（still / draft / final）、`engine`、`artifact_id`、`probe_json` |
| `review_rounds` | 评审轮 | `run_id, round` 唯一；`reviewer`、`caller`、`verdict`、`findings_json`、`fixed_by_version` |
| `pipeline_usage_ledger` | run 级预算账本 | `entry_kind`（reserve / confirm / release）、`amount_micros`、`tasks` |
