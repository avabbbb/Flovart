Flovart is currently a local-first, agent-native visual production workspace. Humans and coding agents operate on the same visible Workflow while providers, API keys, assets and final editing remain under the user's control.

## Current product surfaces

| Surface | Responsibility | Boundary |
| --- | --- | --- |
| **Canvas** | Spatial Workflow for nodes, assets, connections, generation and result editing | Primary creation surface |
| **Table** | Structured media processing and explicit commit back to Workflow/assets | Not a second Workflow authority |
| **Agent** | Discover, prepare, inspect and switch local/external coding agents such as Codex and WorkBuddy | **Not a chat page**; does not embed the built-in Assistant |

Canvas and Table share one contextual right drawer: **Assistant / Context / History**. The built-in Assistant has no extra privilege over external agents and does not manage host installation or connection.

Older designs that made Agent a full-page chat workspace, or removed the top-level Agent surface entirely in favor of one global drawer, are historical only.

## Agent operations

External agents use the Agent Integration Skill + CLI by default. The stable daily surface is:

- `status`
- `workflow.inspect`
- `workflow.selection.get`
- `workflow.apply`
- `workflow.node.run`

`ensure` and `doctor` handle connection setup/diagnostics. The stdio MCP server is an optional projection of the same operation contract, not a second implementation.

Real support levels for Codex, Claude Code, OpenCode, WorkBuddy, DSH and TeleAgent are tracked independently in the [Support Matrix](../../../../SUPPORT_MATRIX.md).

## Workflow and media

Canvas supports image, video, audio, text and configuration nodes plus references, connections, local media tools and visible results.

Table is a structured media-processing view. Results return to Workflow or the asset library through explicit commits; Table does not silently mirror Canvas state.

## Providers and local data

- The visible Browser Workflow remains the current authority for stable agent operations.
- Users configure their own providers; billing, rate limits, cancellation and unknown-submit recovery are verified per provider.
- Browser and Desktop Runtime credential/task boundaries are documented separately.
- Connectors, Skills, projects and logs must not carry raw provider keys.

## Creative hosts

Photoshop, Premiere, After Effects and Resolve are reported only at the evidence level in the [Support Matrix](../../../../SUPPORT_MATRIX.md). Native effects, save/reopen, keyframes and offline export become supported only after real-host verification.
