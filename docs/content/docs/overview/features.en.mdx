Flovart currently provides local-first Workflow and agent creation surfaces. Native effects are the development direction: generate replacement media in AE/PR, adjust a cached result locally, and open Flovart for more complex workflows. This direction is not a shipped capability.

## Current workspaces

| Workspace | Purpose | Boundary |
| --- | --- | --- |
| Workflow | Prompts, references, models, dependencies, tasks and results | Main surface exists; provider behavior requires actual verification |
| Table | Independent node-based media processing | Entry exists; main workbench remains to be implemented |
| Agent | Assistant connection, tasks, context and artifacts | Connection UI exists; deeper two-way sessions require per-agent implementation and verification |

Workflow provides media nodes, PromptBar, connections, local assets and editable generation results. Pending changes for media selection, references, result versions and recovery are listed in [pending verification](../progress/pending-test.mdx).

Each workspace owns its graph and history. Table does not share Workflow nodes; Agent is not another generation graph. The removed Canvas/Art surfaces are not returning.

## CLI, skills and assistants

The current Operation Skill uses the CLI to inspect and operate a visible Workflow. Everyday operations are status, workflow.inspect, workflow.selection.get, workflow.apply and workflow.node.run; ensure prepares the connection. command.list/schema are for discovery, compatibility diagnostics or debugging.

Codex, Claude, OpenCode, DSH, WorkBuddy, and TeleAgent have different integration and verification boundaries. Flovart now ships a local stdio MCP projection for the five stable operations; real TeleAgent import and Agent tracing remain an External Gate. See the [Skill guide](../../../overview/skill-guide.md), [ecosystem architecture](../../../design/ecosystem/TARGET_ARCHITECTURE.md), and [support matrix](../../../../SUPPORT_MATRIX.md).

## Creative software plugins

Experimental PS/PR/AE/Resolve panels and media bridges exist. Real-host selection, processing and import remain to be verified. Native effects, keyframes, project reopening and offline export are planned capabilities; building a panel package does not prove them.

The [main design](../../../design/flovart-native-effects.md) owns the product, interaction, implementation, benchmarks and claim boundaries.

## Local data and models

- Projects, media and generation history are currently stored mainly in the browser; cloud sync is not promised.
- The browser path uses local keys and direct provider requests. Desktop Runtime has a separate credential/task implementation; unified hosting is not a completed claim.
- Users configure model services. Connectors, skills, projects and logs must not receive raw provider keys.
- Real model quality, charges, cancellation and host compatibility require separate evidence.

See the [backlog](../progress/todo.mdx) for unfinished work. Promote features only after actual verification.
